## 1. Three kinds of COUNT

| Expression | Counts | Result on `emp` |
|---|---|---|
| `COUNT(*)` | rows | 7 |
| `COUNT(salary)` | rows where salary is not NULL | 6 |
| `COUNT(department)` | rows where department is not NULL | 6 |
| `COUNT(DISTINCT department)` | different non-NULL values | 3 |

```sql
SELECT COUNT(*)                   AS total_rows,
       COUNT(salary)              AS with_salary,
       COUNT(department)          AS with_department,
       COUNT(DISTINCT department) AS distinct_departments
FROM emp;
```

- `COUNT(*)` counts **rows, not cells**: 7 employees, however many columns the table has.
- **Always alias aggregates.** Unnamed ones all come back as `count`, and the VS Code results grid showed wrong values (7, 3, 3, 3) until each column had its own name.

## 2. SUM, AVG, MIN, MAX skip NULLs

```sql
SELECT SUM(salary) AS total,     -- 39000
       AVG(salary) AS average,   -- 6500
       MIN(salary) AS lowest,    -- 4000
       MAX(salary) AS highest    -- 9000
FROM emp;
```

**The AVG trap:** AVG divides by the number of **non-NULL** values.

| Calculation | Result | Meaning |
|---|---|---|
| `AVG(salary)` | 39000 / 6 = 6500 | average of employees who have a salary |
| `SUM(salary) / COUNT(*)` | 39000 / 7 = 5571 | Nadia counted as zero |
| `AVG(COALESCE(salary, 0))` | 5571 | same as above, written explicitly |

In an interview, ask which one the business wants.

## 3. GROUP BY: one summary row per group

GROUP BY sorts the rows into piles, one per value, then aggregates inside each pile.

```sql
SELECT department,
       COUNT(*)    AS employees,
       SUM(salary) AS total_salary
FROM emp
GROUP BY department;
```

| department | employees | total_salary |
|---|---|---|
| IT | 2 | 16000 |
| Sales | 2 | 13000 |
| HR | 2 | 6000 |
| NULL | 1 | 4000 |

- **NULLs form their own group.** WHERE comparisons drop NULL rows; GROUP BY gathers them into one pile. So 4 rows, not 3.
- HR's total is 6000 (SUM skips Nadia's NULL), but its count is 2 (`COUNT(*)` counts rows).
- **The GROUP BY rule:** every column in SELECT must be in the GROUP BY or inside an aggregate.
- A group can be defined by several columns: `GROUP BY actor_id, director_id` makes one pile per combination.

## 4. HAVING vs WHERE

| | Filters | Runs | Can use aggregates? |
|---|---|---|---|
| WHERE | individual rows | before GROUP BY | No |
| HAVING | whole groups | after GROUP BY | Yes |

```sql
-- Fails: WHERE runs before the groups exist, so there is nothing to count
SELECT department, COUNT(*) AS employees
FROM emp
WHERE COUNT(*) > 1
GROUP BY department;

-- Correct: make the piles, then filter the piles
SELECT department, COUNT(*) AS employees
FROM emp
GROUP BY department
HAVING COUNT(*) > 1;
```

- **Written order follows the frog:** ... **G**ROUP BY, then **H**AVING. Writing HAVING first is a syntax error.
- An aggregate can be used in HAVING without appearing in SELECT.
- **Do I need HAVING?** Ask: "Is there a condition on the groups?" If the task wants every group, there is no HAVING.

## 5. Problems solved

| # | Problem | Key idea |
|---|---|---|
| 596 | [Classes More Than 5 Students](https://leetcode.com/problems/classes-more-than-5-students/) | GROUP BY + HAVING; "at least" means `>=` |
| 182 | [Duplicate Emails](https://leetcode.com/problems/duplicate-emails/) | duplicates = groups with `COUNT(*) > 1` |
| 2356 | [Number of Unique Subjects Taught by Each Teacher](https://leetcode.com/problems/number-of-unique-subjects-taught-by-each-teacher/) | `COUNT(DISTINCT ...)`, no HAVING needed |
| 1050 | [Actors and Directors Who Cooperated At Least Three Times](https://leetcode.com/problems/actors-and-directors-who-cooperated-at-least-three-times/) | GROUP BY two columns |

### 596 · Classes More Than 5 Students
```sql
SELECT class
FROM Courses
GROUP BY class
HAVING COUNT(*) >= 5;
```

### 182 · Duplicate Emails
```sql
SELECT email
FROM Person
GROUP BY email
HAVING COUNT(*) > 1;
```

### 2356 · Number of Unique Subjects Taught by Each Teacher
```sql
SELECT teacher_id, COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id;
```

### 1050 · Actors and Directors Who Cooperated At Least Three Times
```sql
SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(*) >= 3;
```

## 6. Interview questions I can now answer

**COUNT(\*) vs COUNT(col) vs COUNT(DISTINCT col)?**
`COUNT(*)` counts all rows. `COUNT(col)` skips rows where the column is NULL. `COUNT(DISTINCT col)` counts different non-NULL values.

**Difference between WHERE and HAVING?**
WHERE filters rows before grouping and can't use aggregates. HAVING filters groups after grouping and can.

**Is AVG(salary) the same as SUM(salary) / COUNT(\*)?**
Only when there are no NULLs. AVG ignores NULL values, so it divides by fewer rows.

**How does GROUP BY treat NULL?**
All NULLs go into one group of their own.

**How do you find duplicate values in a column?**
`GROUP BY` the column and keep groups `HAVING COUNT(*) > 1`.

## 7. Mistakes I made today

- Wrote HAVING before GROUP BY, twice.
- Added `COUNT(*)` to SELECT when the task asked for one column only.
- Added a HAVING when the task had no condition on the groups.
