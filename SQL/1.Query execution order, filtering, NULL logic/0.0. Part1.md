## 1. Logical execution order

SQL is written in one order and run in another.

**F**ROM → **W**HERE → **G**ROUP BY → **H**AVING → **S**ELECT → **O**RDER BY → **L**IMIT

Memory trick: **F**rogs **W**ill **G**o **H**opping **S**lowly **O**ver **L**ogs.

| Step | What it does |
|---|---|
| FROM | get the data (JOINs happen here) |
| WHERE | drop rows that don't match |
| GROUP BY | put the remaining rows into groups |
| HAVING | drop groups that don't match |
| SELECT | compute and pick the columns (aliases are created here) |
| ORDER BY | sort |
| LIMIT | keep the first N rows |

**Why it matters: an alias can't be used in WHERE, but it can in ORDER BY.**

```sql
-- Fails: WHERE runs before SELECT, so "annual" does not exist yet
SELECT name, salary * 12 AS annual
FROM emp
WHERE annual > 90000;

-- Fix: repeat the expression in WHERE
SELECT name, salary * 12 AS annual
FROM emp
WHERE salary * 12 > 90000;

-- Works: ORDER BY runs after SELECT, so it can see the alias
SELECT name, salary * 12 AS annual
FROM emp
ORDER BY annual DESC;
```

Second fix, using a subquery so the alias exists before the outer WHERE runs:

```sql
SELECT *
FROM (SELECT name, salary * 12 AS annual FROM emp) t
WHERE annual > 90000;
```

## 2. NULL and three-valued logic

NULL means "unknown". It is not zero and not an empty string.

**Rule:** comparing anything with NULL gives *unknown*, and WHERE keeps only rows where the condition is *true*.

```sql
-- Bilal has department = NULL.
-- This silently drops him, because "is unknown different from 'IT'?" is unknown.
SELECT name FROM emp WHERE department <> 'IT';

-- Fix: keep the NULL rows explicitly
SELECT name FROM emp WHERE department <> 'IT' OR department IS NULL;
```

- `= NULL` and `<> NULL` never match. Use `IS NULL` / `IS NOT NULL`.
- `!=` and `<>` are the same operator.
- This behaves the same on every platform (PostgreSQL, MySQL, Snowflake, Databricks, BigQuery).
- NULL-safe shortcut in PostgreSQL / Snowflake / BigQuery / Databricks: `department IS DISTINCT FROM 'IT'`.

## 3. COALESCE and NULLIF

**COALESCE(a, b, ...)** returns the first value that is not NULL, reading left to right.

```sql
SELECT COALESCE(NULL, NULL, 5, 9);   -- 5
SELECT COALESCE(NULL, NULL);         -- NULL

SELECT name, COALESCE(department, 'Unassigned') AS department
FROM emp;
```

- COALESCE changes how a NULL is **displayed**. It does not change the table.
- `IS NULL` in WHERE decides whether a NULL row is **kept**. Different jobs.

**NULLIF(a, b)** returns NULL when the two values are equal, otherwise `a`. Main use: safe division.

```sql
SELECT NULLIF(5, 5);   -- NULL
SELECT NULLIF(5, 0);   -- 5

SELECT revenue / NULLIF(orders, 0) FROM sales;   -- NULL instead of a divide-by-zero error
```

## 4. CASE: if / else inside a query

```sql
SELECT name, salary,
       CASE WHEN salary >= 8000 THEN 'Senior'
            ELSE 'Junior'
       END AS grade
FROM emp;
```

- `THEN` is followed by a **value**, not an assignment.
- Without `ELSE`, rows that match nothing get NULL.
- Always close with `END`, and name the column with `AS`.

## 5. AND / OR precedence and BETWEEN

`AND` is evaluated before `OR`, like `×` before `+`.

```sql
-- Read by the database as:  IT  OR  (Sales AND salary > 7000)
-- so everyone in IT is returned, whatever their salary
WHERE department = 'IT' OR department = 'Sales' AND salary > 7000

-- What was probably intended
WHERE (department = 'IT' OR department = 'Sales') AND salary > 7000
```

**Habit:** whenever AND and OR are mixed, write the brackets.

`BETWEEN` includes both ends: `salary BETWEEN 5000 AND 8000` is `salary >= 5000 AND salary <= 8000`.

## 6. Syntax rules I tripped on

| Thing | Correct in PostgreSQL | Wrong |
|---|---|---|
| Equality | `=` | `==` (Python habit) |
| Text values | single quotes: `'Senior'` | double quotes |
| Column / alias names | no quotes: `AS grade` | backticks, `AS 'grade'` |
| Modulo | `employee_id % 2 = 1` | `employee_id 2 % = 1` |
| Output | exactly the columns, names and order asked for | extra columns |

Other habits:

- When fixing one line, edit the existing query. Retyping loses earlier fixes.
- A query that returns nothing: check the numbers in WHERE before doubting the logic.

## 8. Interview questions I can now answer

**What is the logical order of execution of a SELECT statement?**
FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT. That's why a SELECT alias can't be used in WHERE but can be used in ORDER BY.

**Why does `WHERE col <> 'x'` drop rows where col is NULL?**
Comparing NULL with anything gives unknown, and WHERE keeps only rows where the condition is true. Add `OR col IS NULL`, or use `IS DISTINCT FROM`.

**COALESCE vs NULLIF?**
COALESCE returns the first non-NULL value (used for defaults). NULLIF returns NULL when two values are equal (used to avoid division by zero).

**What does `a OR b AND c` mean?**
`a OR (b AND c)`, because AND binds tighter than OR. Always write the brackets.
