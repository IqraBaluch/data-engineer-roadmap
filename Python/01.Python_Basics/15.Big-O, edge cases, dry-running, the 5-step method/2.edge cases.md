# Edge Cases

An edge case is an input at the extreme end that can break the code.

## Checklist
1. Empty: `[]`, `""`, `{}`
2. One item: `[5]`, `"a"`
3. All the same: `[2, 2, 2]`
4. Ties or duplicates: two equal "best" values
5. Extremes: biggest, smallest, negatives, zero
6. Different lengths: one list or word shorter than another

## Rules
- Test each case, then see what really happens. An empty list breaks `nums[0]`; a one-item list usually does not.
- Guard first: check the empty case BEFORE the line that crashes, and decide clearly what to return.
- Return the same TYPE every time: a function that returns a list returns `[]` (not `-1`); a function that returns a string returns `""` (not `None`).
- Say what you return before coding: a number, a letter, an index, a list?

## Before running any code
- Read each branch aloud: "if this, then add; otherwise subtract".
- For every `[ ]`: what happens on the first and the last position?
- Test with a 1-item and a 2-item input.

## Examples from this folder
- 121: prices only fall, so the profit stays 0.
- 1431: ties count as "greatest" (use `>=`); an empty list returns `[]`.
